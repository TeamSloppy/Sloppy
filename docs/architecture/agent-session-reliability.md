# Agent session inputs and reliable reporting

Native sessions receive PNG, JPEG and WebP attachments as model image segments, alongside file metadata. The limit is eight images, 8 MB each and 24 MB total. Unsupported, invalid or missing images retain an explicit limitation. `files.read` reads UTF-8 text; `images.inspect` loads a readable image and asks the current model a visual question without attaching workspace tools to that model call. Inspection still requires a vision-capable provider.

Recovery transcripts reload the most recent image attachments within the same limits. Older images retain their file references. Delegated workers receive the source user turn's images in their own persisted attachment store, plus source file metadata, rather than the parent's whole conversation.

`long_chat.delegate` advertises a typed assignment object. `acceptanceCriteria` is a string. Legacy JSON-string assignments remain accepted. Validation errors return `invalid_arguments`, a correction hint and `argumentRecovery.invalidFields`; a deterministic failure must be corrected before another call. Incorrect arguments are not permission denials.

Coordinators get at most two recovery passes when a tool fails with correction metadata or a transient error, or when a Build/Debug turn accepts work without creating an assignment. Successful delegation ends recovery immediately. Permission failures, cancellation, pending input and loop/budget stops do not trigger an automatic retry. A successful handoff requires no build/test evidence from the coordinator; execution and verification belong to the worker. A failed handoff remains incomplete.

Each coordinator turn receives a bounded action ledger with counts covering all persisted calls and recent call/result IDs, errors, execution outcomes, process exit codes/timeouts and assignment IDs. A failed call is still an attempt. Assignment absence cannot establish call absence. A successful tool transport does not establish command success when its process exited with a nonzero code. Management-tool results link to their call event; older journals retain FIFO matching for unlinked results. Internal identifiers stay in diagnostics unless the user asks for them; ordinary updates use task titles and distinguish queued, running and delivered work. Implementation skill loading and code inspection belong to workers, so an unambiguous handoff does not repeat that preparation in the coordinator.

Coordinator text is buffered while one tool-free model pass checks operational claims and produces a final correction if needed. Its evidence includes the current turn's calls, bounded argument/result previews for the six most recent calls, and the latest persisted task snapshots with worker summaries, checks, artifacts and limitations. This preserves task IDs separately from assignment IDs and keeps successful report reads available to the reviewer. Worker evidence supports attributed summaries without repeating every verification command; truncation alone is not grounds to deny recorded facts. Binary and credential fields are excluded from previews.

Ordinary conversation without new tool calls skips review, even when the session has old tool history. Durable worker notifications explicitly request review, including when the coordinator used no tools. A correction is final after one pass, so there is no second review request. Invalid review output produces a short unavailable-update message without leaking protocol fields. This semantic check does not use phrase matching and cannot guarantee every model response. Accepted answers retain the warm runtime session; corrected answers invalidate it so the next turn rehydrates the persisted correction instead of the original draft.

Regression coverage includes image bytes reaching the native model and surviving restart, image inspection and readable-root enforcement, actionable delegation errors, corrected coordinator handoff, legacy-call recovery, ledger retention counts, and rejection/correction of the historical false claim that no delegation call occurred.
