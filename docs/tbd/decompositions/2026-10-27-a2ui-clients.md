## Первоначальная стратегия интеграции

Рекомендация: additive API и компоненты сначала, подключение инструментов в последнем PR. Это позволяет обойтись без временного feature toggle. Регистрация tools и выдача скилла выполняются после готовности трёх клиентов.

Альтернатива для раннего пилота: временный выключенный по умолчанию флаг только в точке выдачи UI-tools агенту. Это даёт живую проверку раньше, но потребует отдельного PR удаления флага после общего включения. Текущая карта рассчитана на первый вариант; изменение стратегии согласовать до реализации.

Каждый срез проверяется узкими тестами и соответствующими CI-командами. Перед открытием PR измеряется фактический размер diff. После слияния пересматриваются оценки и границы оставшейся работы. Создание, публикация и слияние PR — отдельные действия, не выполненные этим планированием.

## Следующие продуктовые итерации

Таблицы/фильтры, графики, локальные вычисления, прямые действия, workspace-закрепление и внешний ACP не входят в v1. Для каждой итерации сначала определить пользовательский сценарий, одинаково доступное действие на трёх клиентах и совместимость каталога, затем составить собственные небольшие срезы.

## Завершение v1 в PR #75 — этапы 3–11

- Общий каталог расширен до Text, Column, Row, TextField, CheckBox, ChoicePicker и Button. Добавлены JSON Pointer-привязки, required/range/options validation, общие fixtures brief/comparison/parameters, сохраняемый draft с согласованием новых defaults и стабильным pending actionId. Непроходимые привязки отклоняются до публикации.
- Core принимает действия только для объявленной кнопки и актуальной ревизии; проверяет полный набор значений и владельца long chat/его worker. Приём атомарно фиксируется в существующем durable inbox вместе со snapshot, восстанавливает недописанный журнал и передаёт одно сообщение в прежнюю очередь той же сессии. Обычный approval flow сохраняется.
- Dashboard показывает формы над компоузером, использует кастомный dropdown, хранит черновик/UUID и сохраняет отдельный текст компоузера. API endpoint закреплён за сервером, старые/out-of-order запросы отбрасываются.
- ClientNative использует общий Swift-пакет и нативные TextField/Toggle/Menu/Button, адаптивный Row и прокручиваемую сворачиваемую панель. Подключены основной чат и viewer из карточки агента. При runtime-проверке исправлены пустой sheet первого открытия и запуск загрузки из пустого SwiftUI-контейнера.
- TUI поддерживает Ctrl+Y или `/ui`, Tab/Shift-Tab, стрелки/Space/Enter, Ctrl+U, Escape и переключение форм Ctrl+N/P. Черновик изолирован по серверу/сессии; polling не затирает ввод во время запроса, временная сетевая ошибка сохраняет actionId.
- UI-tools включены в реестр и read-only policy координатора после готовности renderer. Вызовы защищены явным `supportsA2UI` последнего пользовательского сообщения. First-party `sloppy/a2ui` имеет `/a2ui`, autoRoute, ленивое чтение каталога и три примера; provisioning сохраняет пользовательские изменения.
- Пользовательская инструкция и воспроизводимый checklist: [Interactive forms in chat](../../guides/a2ui.md). Новых внешних dependencies нет; SQLite migration не требуется.
