# A2UI clients — proposed implementation slices

- Дата: 2026-10-27. Статус: карта согласована пользователем 2026-10-27; первый срез в работе.
- Продуктовое основание: [A2UI в клиентах](../../product/a2ui-clients-plan.md).
- Цель v1: формы, выбор и сравнение на Dashboard, ClientNative и TUI с продолжением исходного чата.
- Пользователь подтвердил приоритет «формы и выбор вариантов» 2026-10-27. Последующим сообщением «давай сделаем» пользователь разрешил реализацию предложенной карты.
- Бюджет каждого PR: до 600 добавленных и удалённых reviewable lines, включая тесты; документация и утверждённые generated/vendor-файлы не учитываются. Оценки предварительные: если срез не помещается, пересогласовать границу до реализации.
- Существующие изменения в рабочей копии не входят в эту работу. Реализацию начинать в отдельной чистой рабочей копии от актуального main.

PR 1 — первый независимо проверяемый server/API-срез. Тесты входят в каждый соответствующий PR; сквозная проверка в PR 11 не заменяет тестирование предыдущих срезов.

## Предложенная стратегия интеграции

Рекомендация: additive API и компоненты сначала, подключение инструментов в последнем PR. Это позволяет обойтись без временного feature toggle. Регистрация tools и выдача скилла выполняются после готовности трёх клиентов.

Альтернатива для раннего пилота: временный выключенный по умолчанию флаг только в точке выдачи UI-tools агенту. Это даёт живую проверку раньше, но потребует отдельного PR удаления флага после общего включения. Текущая карта рассчитана на первый вариант; изменение стратегии согласовать до реализации.

Каждый срез проверяется узкими тестами и соответствующими CI-командами. Перед открытием PR измеряется фактический размер diff. После слияния пересматриваются оценки и границы оставшейся работы. Создание, публикация и слияние PR — отдельные действия, не выполненные этим планированием.

## Следующие продуктовые итерации

Таблицы/фильтры, графики, локальные вычисления, прямые действия, workspace-закрепление и внешний ACP не входят в v1. Для каждой итерации сначала определить пользовательский сценарий, одинаково доступное действие на трёх клиентах и совместимость каталога, затем составить собственные небольшие срезы.


## Ход реализации

- 2026-10-27: начало PR 1 от актуального `origin/main` (`0d8fd03d`), ветка `codex/a2ui-session-surfaces`, отдельный managed worktree. Незакоммиченные изменения основной рабочей копии сохранены.
- Срез ограничен Text/Column snapshot, обратно совместимым полем сообщения и read API журнала. Производитель и клиенты пока не включаются; временный feature toggle не требуется.
- Пакетные проверки: round-trip JSON, версия/каталог, metadata, shape компонентов, циклы/ссылки/глубина и ограничения размера. Core-проверки: независимое чтение журнала, пересоздание сервиса, последняя валидная ревизия, изоляция сессий, 400/404 и legacy-text fallback.
